## 发布节奏（M6 细则）

1. 交付面定稿（README 状态行只写"版本 + 能力"，不写"已发布"——见 `references/release.md`）。
2. 重生成样例 → 全量测试 → `rm -rf` 临时产物 → 构建（无构建步骤，`git archive`）。
3. 脱敏门 + 布局门 + 离线冒烟 + 确定性双跑全绿。
4. `git tag -a v1.0.0` → push → CI 全绿（含 `--network none` job）。
5. GitHub Release：附件 = 源码包 + `SHA256SUMS`；正文写复验命令（不写包内哈希）。
6. `plan/RELEASE-M6.md` 两栏 + 阶段 7 覆盖对账表；`plan/HANDOFF-M6.md` 收官交接单。

## 风险与处置

| 风险 | 处置（源头在 `plan/01` §9，此处落动作） |
|---|---|
| 与 `npm ci` / `pnpm dedupe --check` 检测重叠 | 每个模块的 DoD 都要求"证明 + 最小解释"字段在场；缺字段即未完成 |
| 区间代数在预发布上出错 | 不自研展开；差分向量覆盖 `data/README.md` §1.1 全 16 条 |
| lockfileVersion 1 语义差异 | 三份解析器 + 混用即退出码 3 |
| MUS 规模爆炸 | `--max-requesters`（默认 12）+ `degraded: true` 显式声明 |
| 上游行为随版本变化 | `semver` 版本钉死 7.8.5；结论带 `implementation` 标签 |
| 灰区默认档被当成事实 | 报告 `policy` 字段回显实际档位；`docs/limitations.md` 声明"默认是策略" |
