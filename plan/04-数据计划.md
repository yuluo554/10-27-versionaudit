## 二、向量集（15 组，`plan/01` §8 结构）

```
fixtures/vectors/
  R1-no-upper-bound/       R2-wildcard-latest/     R3-caret-zero/
  R4-prerelease-unreachable/  R5-empty-intersection/  R6-or-branch-subsumed/
  R7-build-metadata/       R8-bare-version-cross-ecosystem/
  M2-lock-manifest/        M3-lockfile-v1/         M3-lockfile-v2/
  M3-ms-duplicate/         M3-ms-two-targets/      M4-peer-minimal-set/    M5-exit-codes/
```

`M3-lockfile-v1` / `M3-lockfile-v2` 是 M3 新增（`plan/00` M3 的 DoD 要求"三种 lockfileVersion
各有夹具"；v3 由 `M2-lock-manifest` 承担）。`M3-ms-two-targets` 是 **M4 新增**：
`CONVERGIBLE` 的输出必须是**全部**可行目标（两个请求者都声明 `^2.0.0`，2.0.0 与 2.1.3 都要列），
不是挑一个 —— 它同时让差分测试的"目标完整性"面有非空判据。
**退出码 3 的输入形态不进向量集**——那类输入
不产生 JSON 报告，而向量的两条不变量（`input.*` 绑定、`tests/vectors` 无条件 `JSON.parse`）
都要求有报告；它们落在 `tests/exit-codes/lock-input.test.mjs`。

每个目录：`input/package.json` + `input/package-lock.json`（自包含，不依赖 `node_modules`）+
`expected.json`。

`expected.json` 必含：

| 字段 | 作用 |
|---|---|
| `rule` | 向量归属（`R1`…`M5`） |
| `mustContain` | 断言必须出现的字段值（**精确到字段路径 + 值**，如 `findings[0].requesterPath`）。**必须至少含一条 `input.*` 断言**（输入绑定） |
| `mustNotContain` | 防"报得太宽"（如不该出现的 `dependency` 名、不该出现的级别）。**必须指向标量字段** |
| `exitCode` | 端到端期望退出码 |
| `implementationVersions` | `{ "semver": "7.8.5", "node": ">=20" }` |
| `sources` | 支撑该向量的事实锚点（`data/README.md` 的 A 编号 / 章节）；**引用的 A 编号必须真实存在**（幽灵锚点会被 `PROV.COVERAGE` 抓） |

**纪律**：正例反例成对；`mustContain` 为空即视为无效向量（防"断言了全世界"）。

**两条由 M1 复核实测出来的断言纪律**（都已进门，各配变异组）：

1. **输入绑定**：`mustContain` 里至少一条 `input.*`（如 `input.declarations` / `input.packages`）。
   反例断言在**输入被删掉后会真空变绿**——包都不在夹具里，当然不会报。
   没有输入绑定，"同类但不该报"这条纪律就是空的（变异组 `V6` 证伪）。
2. **标量断言**：`{path:"findings", value:"X"}` 解析出**整个数组**，与字符串比恒 false，
   放在 `mustNotContain` 里**永远不会失败**（M0 期 4 条）。要禁某规则出现在某包上，
   写法是 `{"path":"findings[?package=p&rule=R5]", "present": true}`（`present` 表示必须不存在）。

**M2 追加的两条**：

3. **同族多形态反例矩阵**：规则的反例不能只给"单点"（如 R7 的 `plain`），要给**同族形态矩阵**
   （R7：精确 / 范围 + 上界 / 带预发布 / caret / `||` 分支五种正例；无 `+` 的四种反例）。
   理由：单点反例只能证明"这一种写法不被误报"，矩阵才能钉住判据的**边界**。
4. **全帧差分**（`tests/rules/range-diff.test.mjs`，M2 新增）：真跑全部向量，对**每一条** finding
   复算 `expandedRange === validRange(rawRange)`，并复算 M2 的 `satisfies` 与 M3/M4 的 proof。
   与 `expected.json` 的"若干条断言"互补：前者保证**整体**不漂，后者保证**具体**语义正确。
   判据面为空（三类产物全空）时测试报"空转"（变异组 `H8` 钉住）。

**M3 追加的两条**：

5. **M3 判定面独立复算**（`tests/rules/range-diff.test.mjs` 的第三条断言）：对每条 M3 finding
   用**原始 JSON**（自己读 `input/package.json` + `input/package-lock.json`）复算判据，
   **不复用 `src/model/*` 解析器**——复用被测解析器会让"解析错了"与"判据错了"一起错，
   差分就失去意义。覆盖 `manifest-changed-unsynced`（同类键一致就不得报）、
   `missing-from-lock`（锁里确实无该路径、optional 不报）、`lock-extra-undeclared`
   （不得是树外路径解析出的怪名、被声明过就不报）。
6. **"无版本条目"的出口守卫**：`manifest-not-satisfied` 的 `lockedVersion` **不得**为 `null`
   （A23：`satisfies(null,·)=false`，凭它报"不满足"是编造语义；正确出口是 `degraded`）。
   这条让"改回直接判不满足"必红。

## 三、真值纪律（本项目形态）

本项目真值 = **"某个输入下，某个语义断言的结果"**，不是抽样标注集。四条：

1. **真值不存观测**：`expected.json` 只存"输入 + 期望"，不得含运行时产出的 `observed*` 字段。
   期望必须能由**输入 + `data/README.md` 台账 + semver 库**独立复算。
2. **差分双向**：同一向量既跑"工具实现"也跑"直接用 `semver` 库算"，两者必须一致
   （不一致 = 退出码 4 的触发条件，本身是一条**被测行为**）。
3. **不受工具链版本影响**：`semver` 版本在 `package.json` 钉死为 `7.8.5`（不写 `^`）；
   `implementationVersions` 写进每个 `expected.json`，`data/README.md` §1.1 是版本来源。
   换版本 = 必须重跑全部向量并在台账留痕（`data/README.md` §1.1 已有 7.7.4 / 7.8.5 交叉校验记录）。
4. **未实测即未实测**：其他生态（yarn/uv/go/pipdeptree/poetry）的形态**不得进向量**，
   只引官方原文并标注（`data/README.md` §3.4 / §8 的规则：进实现前必须先补测）。

## 六、脱敏与隐私

- 报告与样例：无绝对路径、无主机名、无时间戳、无用户名（`--verbose-paths` 才允许绝对路径，
  且该模式**不进样例**）。
- `fixtures/` 允许真实包名（`send`/`ms`/`debug`/`react`/`widget`）仅限复现实测场景；其余用
  `@fixture/*`（`data/README.md` §6.2）。
- `tools/check-desensitized.mjs` 常驻扫描（四条规则 + 自豁免 + 占位符放行）。
- `resolved` 字段只作字符串留档，**不解析主机**（`data/README.md` §5）。
