# plan/03 · 模块详设

> 上游：`plan/01-题目文档.md` §3｜口径：`data/README.md` §7（三态/退出码/灰区**只在那里定义**）
> 本文件给"每个模块吃什么、吐什么、怎么判、怎么验"。数值定义一律引用不复写。

## M1 `range-lint`

**入参**：`ManifestIR`（含 `overrides`/`resolutions`）+ 可选 `LockIR`（用于取传递依赖声明）。
**出参**：`Finding[]`，字段固定：

```json
{ "rule": "R1", "package": "send", "declaration": "dependencies", "rawRange": ">=1.2.0",
  "expandedRange": ">=1.2.0", "severity": "warning", "evidence": "validRange('>=1.2.0') = '>=1.2.0'" }
```

`expandedRange` **必须**来自 `semver.validRange` 实调（含 `null` 情形要显式写成 `null` 并附原因）。

| 规则 | 判定（实现口径） | 默认级别 |
|---|---|---|
| R1 无上界 | `validRange` 结果里存在无 `upper` 的比较器（`>=`/`>` 且无 `<`） | warning |
| R2 宽范围 | `rawRange ∈ {"*","","x","X"}` 或 `validRange(raw) === "*"`；`latest` 单独判 **非范围**（`validRange === null`） | warning |
| R3 语义收窄 | `^0.x.y` / `^0.0.x` / `~0.x.y`（**用展开结果与意图对比**：上界 `<0.3.0-0` 或 `<0.0.4-0`） | info |
| R4 预发布不可达 | 声明的展开范围 **不** `satisfies` 目标预发布、但基线三元组相同 → 不可达；目标根本不在候选集 → `target-not-in-candidate` | warning |
| R5 空交集 | 单个范围内部（`\|\|` 各分支）求交为空，或 `>=a <b` 且 `a>=b` | **error** |
| R6 分支冗余 | `\|\|` 分支 A 被分支 B 包含（`subset(A,B)` 或展开区间被覆盖） | warning |
| R7 build metadata | 范围字符串含 `+`，且去掉 `+…` 后 `validRange` 不变 | info |
| R8 跨生态误用 | **默认关闭**；开启后对裸版本（`^\d+\.\d+\.\d+$`）给提示"npm 中为精确锁定，Cargo 中为 caret" | info |

R4 的两态必须在输出里区分（`reason` 字段），否则"不可达"会把"根本没这个版本"说成"范围写错"。

## M2 `lock-manifest-check`

**四类 `kind`**（`data/README.md` §7 未定义此四词，定义在此，且是**唯一**定义处）：

| kind | 判据 | 默认级别 |
|---|---|---|
| `manifest-not-satisfied` | 某请求者声明范围 `S`，其解析到的锁定版本 `v` 使 `satisfies(v,S)=false` | **error** |
| `missing-from-lock` | 请求者声明了 `dep`，但锁中该请求者下无对应条目（且非 optional） | **error** |
| `manifest-changed-unsynced` | `lock.packages[""].dependencies` 与 manifest 声明不一致（**最接近 `npm ci` 的基线对照**） | **error** |
| `lock-extra-undeclared` | 锁中包在整棵 manifest 可达图里无请求者（**基于声明图，不依赖 `node_modules` 存在**） | warning |

每条**必须**给：`declaringPackage` / `declaringPath` / `dependency` / `declaredRange` /
`lockedVersion` / `requesterPath` / `explanation`。`requesterPath` 缺失即视为缺陷（这是对
`npm ci` 的补位承诺，见 `plan/00` D1）。

**"锁过期"vs"有意 override"**：默认只报事实；`--strict` 才把"锁中版本 ≠ 声明下界所指最小版本"
升级为 `lock-outdated`（warning）。

## M3 `dedupe-feasibility`

**入参**：同包名的全部锁定版本 + 每个版本的全部请求者（名 + 范围 + 路径），数据全来自锁。

**判定顺序**（`data/README.md` §7.1）：
1. 对每个候选锁定版本 `v` 实算 `∀r satisfies(v, S_r)` → 全通过者进 `targets`。
2. `targets` 非空 → `CONVERGIBLE`（给全部目标，按 semver 升序；`--prefer` 只改标注不改可行性）。
3. 否则求 MUS；`|MUS| < |R|` → `REQUIRES_OVERRIDE`；否则 `NOT_CONVERGIBLE`。

**输出**：
```json
{ "package": "ms", "status": "CONVERGIBLE", "lockedVersions": ["2.0.0","2.1.3"],
  "targets": [{ "version": "2.1.3", "proof": [{ "requester": "debug@2.6.9", "range": "^2.0.0", "satisfies": true }] }],
  "minimalConflictSet": null, "degraded": false }
```

**诚实性约束**：
- `REQUIRES_OVERRIDE` 的 `suggestion` 字段必须带 `"nature": "suggestion"`（不是事实）。
- 无候选但区间非空 → `reason: "no-locked-candidate"`；区间本身为空 → `reason: "empty-intersection"`。
  两者**不许合并**陈述。

## M4 `conflict-explain`

**入参**：peer 声明 + 普通声明 + 锁定版本。
**出参**：
```json
{ "kind": "peer-conflict", "package": "react", "lockedVersion": "18.2.0",
  "minimalSet": [{ "requester": "widget@1.0.0", "range": "^17.0.0", "path": ["<root>","widget"] }],
  "conflictProof": { "ranges": ["^17.0.0","^18.0.0"], "intersects": false,
                     "computedBy": "interval", "crossChecked": "semver.intersects" },
  "degraded": false }
```

- 复用 `src/mus/minimal-set.mjs` **同一份实现**（不另写）。
- 可机械校验的属性：`minimalSet` 去掉任一元素后，冲突消失（property test）。
- ERESOLVE 型与 UNMET 型都要有夹具，且 `docs/limitations.md` 写明 ERESOLVE 报文形态**未实测**
  （`data/README.md` §3.5）。

## M5 `report-ci`

**三格式**：`text` / `json` / `sarif`。JSON 带 `schemaVersion`（当前 `1`）与 `policy`
（本次实际使用的档位表 —— 灰区必须回显）。

SARIF 2.1.0 最小合规：`version`、`$schema`、`runs[0].tool.driver.{name,version,informationUri,rules[]}`、
`results[].{ruleId,level,message.text,locations[].physicalLocation.artifactLocation.uri}`。
`level` 映射：`error → error`、`warning → warning`、`info → note`。

**退出码**沿用 `data/README.md` §7.3（优先级 `3 > 4 > 1 > 2 > 0`）。
`--fail-on` 只影响 1/2 的取舍，不影响 3/4。

**与自证的关联**：每次 `audit` 结束前跑一遍"内部一致性自检"——对每条语义判定，用
`semver` 库直接复算一次；不一致 → 退出码 4 且报告里带 `internal-inconsistency` 条目。
这不是可选装饰：`4` 是"不编造语义"的自证出口。

## 契约冻结（改了就打挂测试）

| 编号 | 约定 |
|---|---|
| K1 | 序列化唯一入口 `src/report/serialize.mjs`；任何模块不得自己 `JSON.stringify` 写盘 |
| K2 | 退出码优先级只在 `src/cli/exit.mjs` 定义一次 |
| K3 | 三态判定顺序（CONVERGIBLE → MUS → 分类）只在 `src/checks/dedupe.mjs` 实现 |
| K4 | MUS 只有 `src/mus/minimal-set.mjs` 一份；M3/M4 都调它 |
| K5 | `semver` 只准从 `src/semver/adapter.mjs` import（AST 守门测试） |
| K6 | 默认档位表只在 `src/policy/severity.mjs`；报告必须回显实际档位 |
| K7 | IR 形态（`plan/02` §三）是模块间唯一契约；三份 lock 解析器产出同形 |
| K8 | 任何"降级"必须带 `degraded: true` + `reason`，不许静默近似 |
| K9 | 版本实现标签（`semver 7.8.5`）只从 `adapter.mjs` 的 `IMPLEMENTATION` 取 |
| K10 | 报告字段顺序由 `src/report/schema.mjs` 驱动，不依赖对象键序 |
