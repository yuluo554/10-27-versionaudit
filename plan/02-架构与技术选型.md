# plan/02 · 架构与技术选型

> 上游：`plan/01-题目文档.md`（需求与验收）｜事实：`data/README.md`（唯一语义来源）

## 一、形态与约束

纯本地 CLI（Node ESM），单仓、单包、无构建步骤。三条不变量：

| 不变量 | 落法 |
|---|---|
| 零联网 | 运行期不 import 任何网络模块；`tools/offline-smoke.mjs` 在进程内把 `dns`/`net`/`tls`/`http` 钩子改成抛错后跑全流程；CI 用嵌套 `docker run --network none` 复核 |
| 默认只读 | 唯一写盘入口是 `--out`（单文件，原子写）；不写 `node_modules`、不改输入、无临时目录残留 |
| 逐字节确定 | 序列化单点（`src/report/serialize.mjs`）+ 固定键序 + 稳定排序 + 无时钟/主机名/绝对路径 |

## 二、分层

```
bin/versionaudit.mjs        # 唯一可执行入口：shebang + 转发（不做逻辑）
src/cli/
  main.mjs                  # 命令分派（audit / <module> / doctor / --version / --help）
  args.mjs                  # 参数面（纯函数：argv → options；未知参数/未知值 → 用法错误）
  options.mjs               # 灰区开关默认值 + 覆盖合并（默认档 = 策略，报告回显）
  exit.mjs                  # 退出码聚合（优先级 3 > 4 > 1 > 2 > 0，一处定义）
src/model/
  manifest.mjs              # package.json → ManifestIR（deps/dev/optional/peer/overrides/resolutions）
  lockfile.mjs              # 版本探测 + 分派（v1/v2/v3）；混用/未知版本 → InputError
  lock-v1.mjs               # 嵌套 dependencies → 统一 IR
  lock-v2.mjs               # packages + dependencies 双视图（必须互相自洽）
  lock-v3.mjs               # 仅 packages
  graph.mjs                 # 声明图：requesterPath / declaringPackage / 可达集
src/semver/
  adapter.mjs               # 唯一允许 import('semver') 的地方；导出带版本标签的原子能力
  interval.mjs              # 自研区间代数：normalize → [lo,hi) 集合 → intersect → isEmpty
  version-order.mjs         # 稳定版本序（compare + 平局规则）
src/rules/
  range-lint.mjs            # M1：R1–R8
  catalog.mjs               # 规则元数据（id/标题/默认级别/依据锚点 data/README 行号）
src/checks/
  lock-manifest.mjs         # M2：四类 kind
  dedupe.mjs                # M3：三态 + 收敛目标
  conflict.mjs              # M4：peer/version 冲突的最小请求者集
src/mus/
  minimal-set.mjs           # MUS：按基数升序枚举 + 上限降级声明（M3/M4 共用）
src/report/
  serialize.mjs             # 唯一写盘/序列化点（键序、排序、LF、原子写）
  text.mjs  json.mjs  sarif.mjs
  schema.mjs                # schemaVersion + 字段顺序表（单一真相源）
src/policy/
  severity.mjs              # 默认档位表（策略，非事实）+ --severity-map 合并
  defaults.mjs              # 灰区默认值（被 options.mjs 消费）
src/errors.mjs             # InputError / UsageError / InternalInconsistency
tests/                      # node:test
tools/                      # 门与一次性脚本
fixtures/vectors/           # 差分向量（输入 + 期望）
fixtures/real-tree/         # 真实树摘录（拓扑保留）
examples/                   # 报告样例（冻结产物）
```

**依赖方向单向**：`cli → checks/rules/report → model/semver → errors`。
禁止 `model/` import `report/`（解析层不知道输出形态），禁止 `checks/` 直接 import `semver`
（必须经 `semver/adapter.mjs`，差分测试靠这一个卡点做对照）。

## 三、统一中间表示（IR）

```js
// ManifestIR
{ name, version, declaringPath: ["<root>"], deps: { "<kind>": { "<name>": range } }, overrides, resolutions }
// LockIR
{ lockfileVersion, packages: [ { path: "node_modules/ms", name, version, deps: {name: range},
                                 devDeps, peerDeps, optionalDeps, dev, optional, link,
                                 resolved: "<string only>" } ],
  rootManifestDeps,           // packages[""] 的 dependencies（v2/v3）；v1 无（空对象）
  rootDevDeps, rootPeerDeps, rootOptionalDeps }   // 根条目其余三类键**分开存**（A22：npm 不跨类合并）
// GraphIR
{ nodes: Map<path, node>, edges: [ { requesterPath, dependency, range, lockedPath, lockedVersion } ] }
```

IR 是**唯一**跨模块契约：三份 lock 解析器产出同形 IR，模块不得感知 lockfileVersion。
`resolved` 只作字符串留档（**不解析主机**，`data/README.md` §5 隐私红线）。

## 四、区间代数与 semver 的分工（关键设计）

| 事 | 谁做 | 为什么 |
|---|---|---|
| 范围展开（`validRange`） | **semver 库** | 不手写近似展开，避免"编造 semver 规则" |
| 单版本满足性（`satisfies`） | semver 库 | 预发布可达性规则（A8/A9）不是纯区间性质 |
| 两两相交（`intersects`） | semver 库，作为**对照基线** | 差分测试用它校验自研求交 |
| 多请求者求交 / 候选落点 | **自研 `interval.mjs`** | 库不提供多路求交（`semver intersection` 检索 total=4） |
| 收敛判定 | 自研 += `satisfies` 实算 | `data/README.md` §7.1 明令不得只用区间非空 |
| MUS | 自研 | 库完全没有这一层 |

**预发布的硬口径**：`interval.mjs` 只为"给出候选与解释"服务；`CONVERGIBLE` 的最终判据是
"该候选 `satisfies` 全部请求者范围"（实算）。区间求交非空但无候选 → 仍然 `NOT_CONVERGIBLE`，
原因写成 `no-locked-candidate`，不伪装成"区间为空"。

## 五、确定性设计（可跑红）

1. **序列化单点**：所有产物只经 `serialize.mjs`（`JSON.stringify` 由键序表驱动，不走对象键序）。
2. **排序键**：`(package, requesterPath.join("/"), lockedVersion, ruleId)`；版本比较用
   `compare()`，不混用字典序（字典序会把 `1.10.0` 排在 `1.9.0` 前）。
3. **禁用面**：`Date`、`Math.random`、`process.cwd()` 绝对路径、`os.hostname()` 在 `src/` 内
   由 AST 守门测试禁止（取值必须经 `src/env.mjs` 注入，便于测试伪造）。
4. **双跑判据**：同输入跑两次 → `Buffer.compare` 为 0；跨 `--format` 三形态各自双跑。
5. **稳定降级**：MUS 超限时的 `degraded: true` 与 `reason` 也进 JSON（否则两次运行可能因
   超时/上限不同而出不同结果）。

## 六、构建与分发

无构建步骤（"骨架即产物"）：

| 项 | 决定 |
|---|---|
| 运行时 | Node ≥ 20（用 `node:test`、`import.meta.dirname` 外的 API 保持 20 兼容） |
| 运行时依赖 | **仅 `semver`，版本钉死 `7.8.5`**（不写 `^`）——语义结论绑定实现版本（`data/README.md` §1.1） |
| 入口 | `package.json` `bin.versionaudit → bin/versionaudit.mjs`；`files` 白名单只含 `bin/ src/ docs/` |
| 包体自足 | 安装后 `npx versionaudit --version` 可跑；`files` 不含 `fixtures/`（向量不进 npm 包，进仓库） |
| 发布产物 | GitHub Release 附件 = `git archive` 源码包 + `SHA256SUMS`（不产 wheel/tarball，见 `plan/06`） |
| Lint | 不引 eslint（新增依赖违反"依赖边界"）；用 `node --check` 语法门 + 测试内断言 |

## 七、被否掉的选项

| 选项 | 否掉理由 |
|---|---|
| TypeScript + 构建 | 骨架期引入 tsc 会让"发布包 = 构建产物"，与"仓库即产物"的确定性双跑冲突；首期纯 JS + JSDoc |
| 自己实现范围解析 | 直接违反 `data/README.md` §1"不编造 semver 规则"；差分测试也没有对照基线了 |
| 用 `semver-intersect` 之类现成库 | 全站 9★、语义不明、无法证明其预发布口径；自研区间代数才有"证明"可谈（这是项目生死线） |
| 读 `node_modules` 判定重复 | 违反只读输入契约（输入只有 manifest + lock）；也会让结论依赖"装没装" |
| worker/多进程并发 | 请求者规模 < 20，收益为零，却引入不确定性（完成顺序） |
| 引入 `yaml`/`ajv` 做 schema 校验 | SARIF 校验用测试内的最小结构断言即可，避免额外依赖面 |
