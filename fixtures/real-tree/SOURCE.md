# fixtures/real-tree —— 真实树摘录

> 状态：**待 M4 落位**（`plan/05` 的"已知未验证项"已登记）。

## 为什么需要它

`plan/01` §3.3 的验收要求：在本机真实树（20 包规模、`ms@2.0.0` 与 `ms@2.1.3` 并存、
`npm ls --all` 退出码 0）上必须给出**确定性结论**。合成夹具可以覆盖规则，但覆盖不了
"真实树的形状"——请求者路径的深度、同名包在不同分支的分布、optional/peer 的混合。

## 落位时要保留什么

**保留**（改了就不背书了）：

- 版本号与范围字符串**逐字不变**；
- 请求者关系（谁声明了谁、声明范围是什么）与路径层级；
- `lockfileVersion` （记录实际版本号）。

**可以替换**（`data/README.md` §6.2 的假包名白名单）：

- 包名：真实包名仅限 `send` / `ms` / `debug` / `react` / `widget` 等复现实测场景的最小用例；
  其余替换为 `@fixture/*` 前缀的假名。
- `resolved` URL：可整体删除或替换为 `https://registry.invalid/…`（工具不解析它，
  但保留会让脱敏扫描多一类噪声）。

## 目录结构（落位后）

```
fixtures/real-tree/
  input/package.json
  input/package-lock.json
  SOURCE.md          # 来源说明：哪几条断言由它背书、怎么导出的、替换了哪些包名
  expected.json      # 与 vectors 同结构（rule/mustContain/mustNotContain/exitCode/...）
```

## SOURCE.md 必须写清三件事

1. **来源**：从哪个项目目录导出、导出命令、导出的锁版本；
2. **背书的断言**：本树支撑 `plan/01` 的哪几条验收（例如"双 `ms` 版本 + npm ls 退出码 0"、
   "20 包规模下的请求者路径深度"）；
3. **替换清单**：哪些包名被换成 `@fixture/*`、有没有删 `resolved`。

## 为什么现在还没有

导出真实树需要在本机选一个"20 包左右、有真实重复版本"的项目目录。M0 不落它是刻意的：
**没有来源说明的真实树看起来像夹具，但会误导读者以为它是实测形态**——那比没有更糟。
